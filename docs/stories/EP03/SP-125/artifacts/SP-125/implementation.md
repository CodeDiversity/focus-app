## Findings and deviations

- **F-125-01 (closed):** Three existing page tests drove secondary filters while the panel was collapsed by construction of the old one-tier bar. Disposition: updated the tests to open the panel first — tests are presentation-owned under this story, and asserted behavior (query params, order toggle) is unchanged. Verified by the full suite.
- **F-125-02 (closed):** Scoped eslint flagged four prettier formatting deltas (`AssignmentRow`, `assignmentPresentation`, page import line, trailing blank). Disposition: `eslint --fix`, re-ran tests green, then hook-managed commit re-applied the same fixers.
- **F-125-03 (open):** `apps/web/e2e/assignments-list.spec.ts` was not executed in this pass — it needs the self-contained stack (API + throwaway Postgres, as used by the SP-124 review's R-124-006 run). Its selectors were checked against the implementation (`Course` label unchanged; dialog `Priority` unchanged; no page-level secondary-filter usage; the edit flow uses the title button, not the pencil). Owner: review unit (DoD-10) — run it (or the manual browser pass) with the reviewer in the loop before sign-off.
- **R-125-001 (closed):** User direction after the first implementation slice: the row Edit control should be a pencil at the end of the cluster, without the outline. Final state: `SquarePen` icon-only `ghost` button (`px-2 max-sm:min-w-[44px]`) placed **after** Delete as the cluster's last control; `aria-label="Edit {title}"` and `data-assignment-focus="edit:${id}"` unchanged. Tab-order assertions in `AssignmentsPage.test.tsx` and `AssignmentsSection.test.tsx` expect Delete before pencil-Edit now (presentation-owned test change; names/hooks preserved).
- **R-125-002 (closed):** User direction: the search field did not read as a search box. Final state: left `Search` magnifier icon via the shared `Input`'s `leftIcon`, placeholder shortened to "Search title or description"; `aria-label="Search assignments"` and debounced query behavior unchanged (161/161 green).
- **R-125-003 (closed):** User direction on top of R-125-002: the search box belongs on its own row so it can be wider. Final state: search is a full-width row in the primary bar; Course, Status, and the Filters toggle line up beneath it; secondary panel unchanged (43/43 page tests green).
- **R-125-004 (closed):** User direction: the secondary controls were unintuitive and the order arrow sat at a detached cell edge. Final state: each secondary filter is one unit — visible label inline-left of its date/select control — and the order arrow is an adjacent fixed-width button inside the Sort-by cell (with `title="Toggle sort order"`), tied by a same-cell test assertion. Accessible names unchanged; 161/161 green.
- **R-125-005 (closed):** User direction with a redesign brief (Linear/Notion/Vercel-style toolbar): primary bar became one connected strip — rounded bordered container on a soft gray ground, search expanding with magnifier and `Search assignments...` placeholder, Course/Status inline at compact `w-40` widths, uniform `h-10` heights with mobile 44px floors, 8px gaps, and the advanced toggle as an icon-plus-badge control whose accessible name stays `Filters`, `Filters (n)`, or `Hide filters` (blue count badge). Panel behavior, clear-filters placement (bottom summary when rows exist, in-card button in the no-match state), and all query/refetch behavior unchanged; a third toolbar-level clear was deliberately not added because the no-match test pins a single clear button in that state. 161/161 green.
- **R-125-006 (closed):** User bug report on R-125-005: the search collapsed to icon-only width, dropdown chevrons sat far from their labels, and the nested toolbar shell doubled borders. **Root cause:** `Input`/`Select` apply `className` to their *inner* control while their own wrappers stay hard `w-full`; in the flex row those `w-full` wrappers were the flex items, so the search wrapper's `flex-1` could not win and each dropdown stretched into its own sliver. **Fix:** width now lives on explicit outer wrappers — search `sm:flex-1 sm:min-w-[280px]`, Course `sm:w-[170px] sm:shrink-0`, Status `sm:w-[150px] sm:shrink-0` — inner controls render `w-full` inside them; uniform `h-[42px]` heights (44px mobile floors), 12px gaps, the nested shell removed (plain row in the card, controls turned `pr-8` to keep label and chevron together), the result-count live region moved below the toolbar above the list, and tablet wraps with search full-width first. Toolbar-proportion test added on the wrappers; accessible names and all query semantics unchanged. One recorded deviation from the brief: on mobile the Course/Status dropdowns remain full-width stacked controls rather than collapsing behind the Filters toggle — CSS-media-gated duplication would double the accessible names in jsdom, and a single responsive control set was kept instead.
- **R-125-007 (closed):** User direction with the Linear/Todoist card brief. **Layout:** the filter toolbar now sits outside a dedicated results card; the always-present live region doubles as the results card's subtle count header and the refetch spinner host. **Card row** (`AssignmentRow` rebuilt): type icon in a neutral tile (`TYPE_ICONS`, `FileText` default), semibold title with a red *Overdue* / amber *Due soon* badge beside it (`isDueSoonAssignment`, ≤3-day window, presentation-only), course-colored chip line under the title (list host passes the nested course; `null` → "No course"; course host renders no line), a neutral meta line (due date · priority · type, plain text replacing the badge cluster), and a `X/Y subtasks` disclosure **only when subtasks exist** (zero-subtask rows show nothing). The right side keeps the compact status pill select and adds an overflow `RowActionsMenu` (ARIA `menu` on the trigger, items with full accessible names, outside-click and Escape close, arrow cycling, first-item focus on open; activating an item re-focuses the trigger so the dialogs keep a valid restoration target). The always-visible Edit/Delete text buttons and the pencil are gone; Edit lives only in the menu and the **title carries the `edit:${id}` hook**, so the shared hook's neighbor-focus contract lands on the neighbor's title. Clicking anywhere on the left section (aside from its interactive children, which stay stacked above the pseudo-element) opens edit on both hosts; the section host now passes `onTitleActivate`. **Focus/behavior invariants kept:** status hook, live-region copy, refetch semantics, D124-10 single owner. Tests updated across `AssignmentsPage.test.tsx`, `AssignmentsSection.test.tsx`, `CourseDetailPage.test.tsx` (menu-driven delete, neighbor-title focus, no zero-subtask disclosure) plus one new page test for the menu keyboard model; the e2e spec's delete step now goes through the menu (F-125-03 not-run disclaimer unchanged). Full web suite 687/687; typecheck and repo-wide eslint clean.
