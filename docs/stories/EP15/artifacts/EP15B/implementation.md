## Deviations

1. **Day-bound entries validated in the service, not a nested DTO:** `FieldValidationPipe` only maps top-level constraints into `errors`, so a nested DTO would have produced `message`-only failures; the service keys each failure `days[<i>].<field>` (DoD-4). The DTO still enforces the array shape for the pipe.
2. **`null` on non-nullable PATCH fields reads as omitted** (`energy`, `startDate`, `startTime`, `endTime`, `effectiveFrom`), the `availability.service.ts` precedent; `title`, `courseId`, `endDate`, `weekdays` take `null` as a value (EP14E D-E4 precedent). Recorded in contracts.md.
3. **Parameter 400s precede the ownership lookup** for `?from=` and `:date` (request-shape errors, no oracle: both leak nothing about any row); the uniform 404 still wins for a foreign block with a well-formed value.
