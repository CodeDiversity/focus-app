**(b) EP14E identity.** The plan is sound, though not yet proven. With every window NORMAL, `energyOf` defaults to NORMAL (`intervals.ts:4–5`) and `byEnergyPreference` ranks every gap equally. Its stable sort with an index tiebreak (`scheduler.ts:124–129`) returns earliest-first whatever `demanding` is. So the hard flag cannot change all-NORMAL output, and a guard that only acts when a LOW gap exists is a no-op there. The flag does not appear in `SchedulerOutput`. Critical work (`preferEnergy = false`, `:363`) is untouched. The EP14E-AC2 test "identity case extended with flags set" is the right owning test. The guard must also be the identity when no LOW gap exists, which the R-EP14-07 edge case (ii) makes explicit.

**(c) EP14A CI.** Widening `push` changes nothing else. There are no new jobs and the services are unchanged. `JWT_SECRET` comes from `secrets` and is available on same-repo pushes, as today. A `branches` filter excludes tag pushes. Gitleaks now runs on every branch, which is harmless. There is no `concurrency` block (R-EP14-09 item 5). The red/green proof is operationally safe: there is one workflow and no deploy step, and it uses a scratch branch with push authorization recorded (README). The branch should be deleted afterwards. The proof is unachievable as sequenced (R-EP14-01).

**(d) Sizing and ownership.** EP14B (3 ACs, three contract fixes in one backend pass; D-R8 folding is justified), EP14C (3), EP14D (4) and EP14E (4; refiner gate recorded) meet the default slice. EP14A falls below the gate (R-EP14-02). Every AC-E14 and TR-E14 has an owner. AC-E14-07's owner is "this breakdown" (R-EP14-09 item 3). The DoD mapping in the README agrees with each story's DoD section.

**(e) Backlog triggers.** BL-14-02, -03 and -06 are concrete. BL-14-01, -04 and -05 are weak (R-EP14-09 item 4). `queue-lint` rule 6 passes, but it checks shape, not checkability.
