The page renders exactly **one** `[data-assignment-focus="add"]` control and **zero** `[data-assignment-focus="empty-add"]` controls. The trigger is never disabled and never shows a busy state; the shared form's own submit button carries the request's busy state.
2. **The create round-trip.** The trigger opens the shared create form (the shared `AssignmentDialogs` + `AssignmentForm`, unchanged), whose create mode offers the **course select** populated with the student's own courses; a student with no courses can still create a course-less assignment (D05-15). 3. **The empty states.** Each of the four sections renders the shared `EmptyState` with its own icon and the content supplied through EP05B's `emptyState` prop — the exact title and description under **Decisions → #9**. The two **assignment** sections' empty state offers a `primary` **"Add an assignment"** button that opens the same shared create form; the two **calendar** sections' offer an outline link to `/calendar` — **"View your week"** (classes) and **"Open the calendar"** (study sessions). Its host supplies `items`, `onChanged`, `onSubtaskChanged`, `onSubtaskRefresh` and optionally `onPending`/`onFormOpen`. **This hook is the reusable owner EP05C must use** rather than writing a second create flow.

The dashboard therefore attaches `actions.sectionRef` to the page's root `<section>` (EP05B → Decisions #12) — the header, and therefore the "Add assignment" control, is inside it.

The **post-delete** effect (`:240-260`) looks for `[data-assignment-focus="empty-add"]` and **falls back to `[data-assignment-focus="add"]`** when it is absent — so the dashboard needs no `empty-add` control at all.

### Design decisions (planner-recorded)

1. **One action, not two inert ones.** The placeholder's "Create Study Plan" and "Start Focus Session" are omitted rather than shipped disabled (D05-5). EP07 deliberately left its button inert because EP05 owns this surface (D07-9); EP05 now decides it does not appear until EP07 lands. Recording this here closes the D07-9 seam explicitly rather than leaving a dead button on the page.
2. **The shared owner does the work, and it is the only one.** The dashboard does not implement its own create form, its own validation or its own focus handling — it mounts `AssignmentDialogs` with `useAssignmentActions` **once** and points `onChanged` at the RTK Query refetch. Two create flows would drift; two owners of the same page would also fight over the focus target (D05-17). The page host — not a section — owns the hook and exposes the `onOpenDetails(row)` callback that EP05B's rows call.
3. **No optimistic insert.** The new assignment appears only after the server confirms it (the assignments query is refetched). A dashboard that shows an unconfirmed row would show work the server rejected.
4. **The empty states name real next steps.** Every empty state points at something the student can actually do from the dashboard (add an assignment, open the calendar). No empty state mentions a study plan or a focus session (D05-5).
5. **The parent index belongs to this child** — the last substantive child owns the combined evidence record (the sizing policy: no index-only or verification-only child). The reviewer's `review.md` and `walkthrough.md` are **not** this child's output.

### Decisions (the `ui-refiner` pass — 2026-10-30, D05-12)

One line per question and answer. These are settled; later agents rely on them. EP05B's decisions are binding and are **not** re-opened here.

1. **The quick-actions layout** → **Not a card.** The one action renders in EP05B's reserved slot in the page header's **action group**, as the group's **first** control (before "View Profile"), in the DOM position EP05B fixed (header → refresh → quick-action slot → "View Profile"). The placeholder's "Quick Actions" card is not rebuilt (D05-11).
2. **The action's label** → **"Add assignment"** — the EP03 host copy (`AssignmentsSection.tsx:95`, `AssignmentsPage.tsx:306`), so the same control reads the same on the dashboard and on the assignments page. The placeholder's "Add New Assignment" is dropped.
3. **The action's icon** → **`Plus`** (16 px, `aria-hidden`), passed as the shared `Button`'s `leftIcon` (the Button wraps it in an `aria-hidden` span, `Button.tsx:77`). The button's accessible name stays exactly "Add assignment". Verified present in `lucide-react@0.312.0`.
4. **The action's variant** → **`primary`** (the shared Button's default). It is the page's one primary action; "View Profile" keeps `outline`, so the header shows a clear primary/secondary hierarchy.
5. **The action's busy state** → **none on the trigger.** It is a pure trigger: never `isLoading`, never `disabled`, no `aria-busy`, no spinner. The request's busy state belongs to the shared form's submit button (`isLoading` → spinner + `aria-busy` + disabled, `Button.tsx:50-73`), and the post-create refresh is already signalled by EP05B's live-region spinner. Disabling the trigger while the dialog is open would break the shared form's focus restoration (`AssignmentForm.tsx:149-155`).

### Remaining risks / implementation notes (not blockers)

- **The hook needs `items`.** `useAssignmentActions` requires the host's visible rows; the dashboard passes its derived rows (memoized with `useMemo` so the hook's items-identity effect does not run on every render). The hook's focus neighbours behave sensibly here because the dashboard exposes no delete and no status control.
- **The post-create focus target must exist.** The hook focuses `[data-assignment-focus="add"]` after a create; the dashboard's action control carries it (the assignments page's precedent, `AssignmentsPage.tsx:301-307`; the section host's precedent, `AssignmentsSection.tsx:94`).
- **One owner, one mount (D05-17).** A second `useAssignmentActions` instance or a second `AssignmentDialogs` mount on the dashboard would give two dialog states and two focus owners, and the hook's post-create focus effect would become non-deterministic. The owner lives in the page host only; the sections receive the `onOpenDetails(row)` callback as a prop.
- **The focus lookup is scoped to `sectionRef`.** The "Add assignment" control must be **inside** the element that carries `actions.sectionRef` (the page's root `<section>`), or `focusControl` finds nothing and focus is lost after a create (`useAssignmentActions.ts:86-88`).
- **Cache refresh, not a manual merge.** Use the assignments query's `refetch()`; do not patch the cache by hand (a hand-patched row would diverge from the endpoint's projection and its order). The slice defines no tags, so a tag invalidation is not available.
- **The create form's course select.** `courses` must be supplied (the existing plain-axios `listCourses()`); the select is otherwise a dead one-option control. Mixing one plain-axios read into an RTK Query page is a deliberate, recorded trade-off of D05-1 (A3).
- **The dialog's placement.** The shared `AssignmentForm` is a focus-managed panel; mounting it from the dashboard must not break the page's focus order or trap focus outside the dialog (the shared component owns the trap).
- **The live region is EP05B's.** EP05C prepends its action sentence to that region and clears it on `onFormOpen`; it must not add a second `role="status"`/`role="alert"` region, and it must not change the region's role, position or styling.
- **The empty states and the sections must agree** — the section components (EP05B) and the empty-state content (EP05C) are two halves of one decision; the `ui-refiner` pass covers both children, so the copy is settled once.
