## Summary

Rebuild the dashboard page around four real sections — today's classes, upcoming deadlines, overdue assignments and today's study sessions — each rendered from the data EP05A derives, each with a limit, a "see all" link to the corresponding full list, and its own loading, empty and error state. The placeholder's static cards are removed (D05-11).

## Description & bounded scope

### In scope

1. **The four section components** in `apps/web/src/features/dashboard/ui/` — each one owns its heading, its rows, its limit, its "see all" link and its three states, and each one applies its own EP05A selector and limit to the data it is given:
   - `TodayClassesSection.tsx` — today's `CLASS` events (`selectTodayClasses`): the time range, the event title and the course name; capped at 5; "see all" → `/calendar`.
   - `UpcomingDeadlinesSection.tsx` — unfinished, not-overdue assignments (`selectUpcomingAssignments`): the due date shown; a null `dueDate` labelled ("No due date"); capped at 5; "see all" → `/assignments`.
   - `OverdueAssignmentsSection.tsx` — unfinished assignments whose `dueDate` is in the past (`selectOverdueAssignments`): each row marked with the text label "Overdue" (never colour alone); capped at 5; "see all" → `/assignments`.
   - `TodayStudySessionsSection.tsx` — today's `STUDY_SESSION` events (`selectTodayStudySessions`); the focus flag shown as text ("Focus session"); capped at 3; "see all" → `/calendar`. Renders an empty state until EP06/EP07 create sessions (D05-2).
2. **A shared section module** — `apps/web/src/features/dashboard/ui/dashboardSection.ts` (new): the shared UI types (`DashboardSectionStatus`, `DashboardEmptyState`) and the two shared row helpers (the event time range, the due-date label). Six consumers (four sections, the page, EP05C's empty-state content) need the same vocabulary; duplicating it four times would let it drift.
3. **The dashboard page** — `apps/web/src/pages/dashboard/ui/DashboardPage.tsx` is rebuilt: the header block (heading, greeting, the day line with the refresh control, the action group), the page's live region and the four sections in the settled grid. The placeholder's quick-action card, its static "Recent Assignments" card, its static "Study Stats" card and its static "Upcoming Deadlines" card are removed (D05-11) — the working "Add assignment" action is EP05C's. The "Recent Assignments" and "Upcoming Deadlines" cards are **superseded** by the upcoming/overdue sections; the **"Study Stats" card is removed and not rebuilt in any form** (D05-11, **final**): its two values ("0 Hours Studied" / "0 Tasks Completed") have no data source — "Hours Studied" waits for EP07's `GET /study-sessions/confirmed-time` (D07-3) and "Tasks Completed" is not one of the epic's scope items (V-05-2). This rebuild is an explicit **replacement** of the placeholder, not a silent omission.
4. **The "open relevant details directly" affordances** (the second half of AC-E05-05): a class row's title is a native link to the course (`event.link` → `/courses/:id`); an assignment row's title calls the page-level `onOpenDetails(row: AssignmentListItem): void` callback — **the row never mounts the shared assignment owner and never opens a dialog itself** (the callback contract and its single owner are fixed in the shared contract section of the README, D05-17); a study-session row has **no** deep link today (`events[].link` is `null` for sessions — verified) and is rendered as non-interactive text.
5. **A dashboard-local compact assignment row** — `apps/web/src/features/dashboard/ui/DashboardAssignmentRow.tsx` (new), rendering the fields settled under **Decisions → #4**. **`AssignmentRow.tsx` and the rest of `features/assignments/ui/` are not modified** (D05-18 — `AssignmentRowProps` has no summary variant and every prop is required, so reuse would force an unscoped edit to a shared EP03 component).
6. **Tests** for the four sections and the page (TR-E05-02, TR-E05-03, TR-E05-04, TR-E05-07).

## Acceptance criteria

1. **The page frame, the day label and the section layout.** The dashboard renders inside a `max-w-5xl` shell with `px-4 sm:px-6 lg:px-8` (the Calendar and Assignments pages' measure). Its header block carries the `<h1>Dashboard</h1>`, the retained greeting (`Welcome back, {name}!`), the **day line** and the action group. The **day line** reads `Today, Oct 30, 2026 · America/New_York`, built from the payload's `today` and `timeZone` (the client's own time zone is never used for it) and it is **absent** while the calendar query has no payload. The action group holds, in order: the reserved quick-action slot (EP05C's "Add assignment" — an empty slot until EP05C lands) and the "View Profile" link; the **refresh control** (a ghost icon button named "Refresh dashboard" that recomputes the request window and refetches both queries) sits immediately after the day line. Below the header, one page-level `role="status"` live region announces the loaded state and the four counts; below it, the four sections sit in a `grid gap-6 lg:grid-cols-2` in **urgency order — Overdue assignments, Upcoming deadlines, Today's classes, Today's study sessions** — one column below `lg`, and the DOM order, the visual order and the tab order are the same at every width. The page contains **no** leftover placeholder content: no "Study Stats" card, no "Hours Studied" or "Tasks Completed" figure, no hard-coded "No assignments yet", and no inert "Create Study Plan" / "Start Focus Session" buttons (D05-11, final).

2. **Today's classes.** The dashboard shows a labelled region ("Today's classes") whose rows are today's `CLASS` events (`selectTodayClasses`, keyed on the server-echoed `today`): each row shows the time range (`09:00 – 10:00`, or just `09:00` when `endTime` is null), the event title and the course name. The title is a native link to `event.link` (`/courses/:id`) when the payload carries one and plain text when it does not. A `CLASS` event on another day is never rendered. The rows keep the payload's order (no client-side re-sort). The section is capped at **5** rows and shows `+N more` when it truncates; its "See all" link points at `/calendar`.

3. **The two assignment lists and the compact row.** The "Upcoming deadlines" region lists the incomplete assignments that are not overdue, in the endpoint's order (no client-side re-sort), with a null-`dueDate` row last and labelled **"No due date"**; the "Overdue assignments" region lists the incomplete assignments whose due date has passed, each row marked with the **text** "Overdue" in addition to colour. Both regions render the **dashboard-local compact row** (`DashboardAssignmentRow.tsx`): the **title** (a `<button>` that calls the host-supplied `onOpenDetails(row)` **once**, with the row it rendered, and that carries `data-assignment-focus="edit:<id>"`), the **course** (`code · name`, or "No course"), and the **due date** (`Due Oct 30, 2026`, or "No due date") with the **subtask progress** (`2/4 subtasks`) when the assignment has subtasks. A compact row carries **no** status select, no overflow menu, no status badge, no priority or type label, no "Due soon" badge and no subtask checklist. The row mounts **no** dialog and **no** assignment owner (D05-17). Both regions are capped at **5** rows with `+N more`, and their "See all" links point at `/assignments`.

4. **Today's study sessions.** The dashboard shows a labelled region ("Today's study sessions") whose rows are today's `STUDY_SESSION` events, each with its time range and title; a **focus** session carries the text **"Focus session"** and a non-focus session carries no focus label. A session row is **not interactive** (there is no deep link for a session — `events[].link` is `null`) and must not render a link that goes nowhere. The section is capped at **3** rows with `+N more`, its "see all" link points at `/calendar`, and it renders an empty state until sessions exist (no session is created by EP05).

5. **Per-section states, independence, responsiveness, keyboard and reduced motion.** Every section renders **its own** loading state (a skeleton of `animate-pulse motion-reduce:animate-none` bars with `aria-busy`), **its own** empty state (the shared `EmptyState` with the section's icon, its title/description/action coming from the `emptyState` prop) and **its own** error state (a `role="alert"` box with the `getErrorMessage` text and a "Try again" button that refetches that query). The two queries fail **independently**: a failing assignments query shows the error in the two assignment sections only, and a failing calendar query shows the error in the two calendar sections only — neither blanks the other pair. Below `lg` the sections stack in one column in the same order, every interactive element in a row is ≥ 44 px tall, the meta lines wrap and nothing forces horizontal scrolling. Each section is a named region (`<section aria-labelledby>` + `<h2>`), the tab order is the DOM order, every control carries the EP10 `focus-ring` focus treatment, and the overdue marking survives a greyscale check because it is text. **No** element carrying an `animate-*` class lacks the `motion-reduce:animate-none` companion, and no other motion is introduced (all other transitions use the EP10 `duration-*` tokens).

### Design decisions (planner-recorded)

1. **Four section components, one page.** Each section owns its own heading, its rows, its limit, its "see all" link and its three states. The page composes them and owns the page-level heading, the day/time-zone label and the live region.
2. **The deadline sections show assignment rows, not calendar chips.** The calendar's `ASSIGNMENT_DEADLINE` events are not used for them: the assignment rows carry course context, subtask progress and the assignment's own status, and a single source per section avoids two competing presentations of the same work.
3. **The endpoint's order is the section's order** (D05-9) — the sections never re-sort.
4. **The overdue marker is text.** The row shows the word "Overdue" (`OVERDUE_LABEL`) in a `Badge`; colour is an addition, never the signal.
5. **The class row links to the course** via the payload's `link` (`/courses/:id`); the assignment row's affordance is settled by the `ui-refiner` pass (**Decisions → #6**: the shared edit dialog through the page-level `onOpenDetails(row)` callback — D05-17's contract is unchanged); the study-session row has no deep link today and is not given a fake one — it is non-interactive.
6. **The page removes the placeholder's static content** (D05-11). The "Quick Actions" card is removed here and re-added as a working block by EP05C (an accepted inter-commit transient). The "Study Stats" card is **removed and not replaced by any equivalent** (D05-11, final): shipping hard-coded zeros asserts a false fact to the student, and no real data source exists for either value.
7. **A dashboard-local compact row, not a reduced shared `AssignmentRow`** (D05-18). `AssignmentRowProps` (`apps/web/src/features/assignments/ui/AssignmentRow.tsx:112-134`) has **no** summary variant and every prop is **required** (`statusValue`, `statusDisabled`, `expanded`, `busy`, `onStatusChange`, `onToggleExpanded`, `onOpenEdit`, `onOpenDelete`, `onTitleActivate`, `onSubtaskChanged`, `onSubtaskRefresh`, `onSubtaskBusyChange`), so reusing it with reduced props would require editing a shared EP03 component that the assignments list page and the course page's `AssignmentsSection` consume. EP05B builds `DashboardAssignmentRow.tsx` under `features/dashboard/ui/` instead; **which** fields it shows is settled under **Decisions → #4**. No EP03 shared component is modified.

### Decisions (the `ui-refiner` pass — 2026-10-30, D05-12)

One line per question and answer. These are settled; later agents rely on them.

1. **Section layout and information hierarchy** → The page is a `max-w-5xl` shell (the Calendar/Assignments pages' measure, not the placeholder's `max-w-7xl`); a header block (`<h1>Dashboard</h1>`, the retained greeting, the day line with the refresh control) sits above a `grid gap-6 lg:grid-cols-2` of the four sections in **urgency order — Overdue assignments, Upcoming deadlines, Today's classes, Today's study sessions** — one column below `lg`, with the DOM order, the visual order and the tab order identical at every width. The student therefore sees **what needs attention first** (the overdue work), then the deadlines to plan against, then the day's schedule. The canonical section headings are **"Overdue assignments", "Upcoming deadlines", "Today's classes", "Today's study sessions"** (the epic's scope wording), each an `<h2>` with a decorative icon — `AlertTriangle`, `ClipboardList`, `GraduationCap`, `Brain` — so a section is identifiable without colour. The quick-action area is a **reserved slot in the header's action group** (right of the heading, before "View Profile") that EP05C fills — EP05C never moves it.
2. **How "today" is communicated** → One muted line under the greeting: `Today, Oct 30, 2026 · America/New_York`, built from the payload's `today` and `timeZone` with ``formatDate(new Date(`${today}T12:00:00Z`), timeZone)`` — the noon-UTC construction already used by `CalendarEventDetails.tsx:89` (EP04's F3 fix). The client performs **no** zone arithmetic; the line is **absent** while the calendar query has no payload (the calendar sections show the error instead). The raw IANA id is shown, exactly as the calendar page shows it (`CalendarPage.tsx:156`).
3. **The section limits and their "see all" links** → **D05-10 is confirmed unchanged**: classes **5** → `/calendar`; upcoming deadlines **5** → `/assignments`; overdue **5** → `/assignments`; study sessions **3** → `/calendar`. Reason: five rows is the most a student can scan without scrolling in the three work sections, and a day's sessions are a glanceable summary rather than a work queue. The visible link text is **"See all"** in every section, with a section-specific `aria-label` (`"See all today's classes on the calendar"`, `"See all upcoming deadlines on the assignments page"`, `"See all overdue assignments on the assignments page"`, `"See all today's study sessions on the calendar"`) so four identical labels stay distinguishable to a screen reader (WCAG 2.5.3 — the visible text is contained in the accessible name). The truncation remainder is shown as **`+N more`** under the rows.
4. **The two assignment lists' row form** → `DashboardAssignmentRow.tsx` renders three lines: the **title** (a `<button type="button">` that calls `onOpenDetails(row)` and carries `data-assignment-focus="edit:<id>"`), the **course** (`code · name`, or "No course" when `course` is `null` — D05-15), and the **due date** (`Due Oct 30, 2026` via `formatDate(new Date(dueDate), timeZone)`, or **"No due date"** when `dueDate` is `null`) with the **subtask progress** (`2/4 subtasks`) appended only when the assignment has subtasks. The row carries **no** status select, no overflow menu, no status badge, no priority, no type label, no "Due soon" badge and no subtask checklist — reason: both sections contain only unfinished work, so a status badge would mostly repeat "Pending", the due date is already the urgency cue, and the section heading carries the framing. The **overdue** marking is the shared text badge `<Badge variant="danger">{OVERDUE_LABEL}</Badge>` on the title line — the word "Overdue" is present, so the marking survives greyscale and colour-vision deficiency; the badge's `danger` variant already carries `OVERDUE_STYLE`'s classes.
5. **The study-sessions presentation** → A session row shows the time range (`09:00 – 10:00`, or just `09:00` when `endTime` is `null`), the event title and — **only** for a focus session — a `Badge` reading **"Focus session"** (`variant="accent"`). A non-focus session carries no focus label (the section heading already says "study session"). The session row is **not interactive**: `events[].link` is `null` for sessions, so the row renders no link, no button and no details dialog — the section's "See all" link to `/calendar` is the only way out.
6. **The details affordance** → **The assignment row's affordance is the shared edit dialog**, reached through the mandatory callback: the row's title button calls the page-level `onOpenDetails(row: AssignmentListItem): void`, and the EP05C-owned host forwards it to `actions.openEdit(row)` (D05-17 — one owner, one mount). **Plain navigation to the course page is not the affordance**; the row's course is text, not a link, and the row's own course navigation would compete with the one callback the contract fixes. This **closes PR-010**: AC #3 and its test stand exactly as written (the callback is called once, with the row it rendered) and no clause has to be rewritten. The **class** row's title is a native `<Link to={event.link}>` (the payload's `/courses/:id`), and plain text when the payload carries no link.
7. **The per-section loading, empty and error presentation** → Each section renders **its own** three states: a **skeleton** of three `animate-pulse motion-reduce:animate-none` bars with `aria-busy="true"` on the section (the calendar page's `animate-pulse` precedent, `CalendarPage.tsx:167`); the shared **`EmptyState`** (icon + `title`/`description`/`action` from the `emptyState` prop, the section's own icon); and an **error box** (`role="alert"`, `border-danger/30 bg-danger/10`, the `getErrorMessage(error)` text, and a **"Try again"** `Button` that refetches that query and shows the shared busy spinner while it is in flight). The section's error copy falls back to a per-section sentence ("We could not load your classes. Try again." and its three siblings) when the message is empty. The two queries fail **independently**: a failing calendar query shows the error in **both** calendar sections (they share one query) and leaves both assignment sections rendering their rows, and the mirror image holds for the assignments query — a failed query never blanks the other pair.
8. **375px responsive behaviour and keyboard / focus order** → Below `lg` the sections stack in one column **in the same order**; each row's interactive element is ≥ 44 px (`max-sm:[&_button]:min-h-[44px] max-sm:[&_a]:min-h-[44px]` on the row list, the `AssignmentsSection.tsx:109` pattern), the meta lines wrap, titles wrap rather than truncate, and no fixed width forces horizontal scrolling (the `max-w-5xl`/`px-4 sm:px-6 lg:px-8` shell, the `CoursesPage.test.tsx:424` class-contract precedent). The **tab order is the DOM order**, which is the visual order: header (refresh → quick-action slot → "View Profile") → per section the "See all" link (in the section's heading row) → the rows' controls. Each section is a **named region** (`<section aria-labelledby="…-heading">` + `<h2>`), the heading level below the page's `<h1>` is `<h2>` (and the shared `EmptyState`'s `<h3>` sits correctly inside it), and every control carries the EP10 **focus-ring** treatment explicitly (`focus-visible:ring-2 focus-visible:ring-focus-ring focus-visible:ring-offset-2`) so the focus ring is assertable in a test.
9. **Reduced motion (TR-E05-07)** → The dashboard introduces **no new motion**. The only animations are the section skeletons' `animate-pulse` and the shared `Button`'s busy spinner (`Button.tsx:55`); both carry **`motion-reduce:animate-none`**, and the page's existing auth spinner keeps its own (`DashboardPage.tsx:11`). Every other transition uses the EP10 `duration-*` tokens, which the global `prefers-reduced-motion` block (`apps/web/src/index.css:120-135`) collapses to 0.01 ms. The test asserts the **general property**: no element carrying an `animate-*` class lacks the `motion-reduce:animate-none` companion — so a later addition of an animation without the companion fails the test.
10. **The refresh control** → A ghost icon button named **"Refresh dashboard"** sits immediately after the day line. It recomputes the request window (`dashboardTodayRange()`) so a tab left open across midnight re-reads the server's "today" (EP05A §7's open item) and refetches **both** queries. When the recomputed window differs from the current one, the calendar query refetches through its argument change — the handler must not issue a second, stale-window request.
11. **The page's live region** → Exactly **one** page-level `role="status"` region, in the assignments page's count-header style (`text-xs font-medium uppercase tracking-wider text-text-muted`), between the header and the sections. It reads "Loading your dashboard…" while the first load is pending and then the **count summary** of the four derived sets (`3 classes today · 1 overdue assignment · 5 upcoming deadlines · 0 study sessions`, with singular/plural handled). The counts are the **uncapped** totals, so a capped section never under-reports. The sections have no live regions of their own.
12. **The focus targets on the dashboard** → The page renders exactly **one** `data-assignment-focus="add"` control (EP05C's "Add assignment") and **no** `data-assignment-focus="empty-add"` control: the shared hook's post-delete effect falls back to the `add` control when `empty-add` is absent (`useAssignmentActions.ts:244-250`), so "at most one `empty-add`" is satisfied by having none. The compact row's title button carries `data-assignment-focus="edit:<id>"` so the hook's neighbour-focus after a delete or a status change finds a real target. The page's root `<section>` is where EP05C attaches `actions.sectionRef`, so the hook's focus lookups can reach the "Add" control.
13. **The course colour** → The dashboard does **not** use the course colour. The course name (class rows) and the course code + name (assignment rows) are the identifying cues; the colour border of the calendar chip and the colour dot of the assignments row stay where they are, so the dashboard does not introduce a third treatment of the same cue inside the EP10 token palette.
14. **The empty-state mechanism** → Each section takes an optional `emptyState?: { title: string; description?: string; action?: ReactNode }` prop and renders the shared `EmptyState` with the section's own icon. **EP05B's page passes provisional titles** ("Nothing overdue", "No upcoming deadlines", "No classes today", "No study sessions today"); **EP05C replaces the content** (title, description and the action that opens the shared form) **through the same prop, without touching the section components** — which keeps D05-12's rule intact (EP05C may not change a section's shape, its row form or its data contract).

### Remaining risks / implementation notes (not blockers)

- **The session row has no link.** `events[].link` is `null` for `STUDY_SESSION` — a session row must not render a link that goes nowhere.
- **The empty study-sessions section is the expected state today.** It must not read as an error, and it must not say "no sessions scheduled" in a way that implies the feature is broken (D05-2, D05-13) — the copy is EP05C's (Decisions → #14).
- **Row density.** The full `AssignmentRow` carries a status select and a subtask disclosure; a dashboard row is a summary. **Resolved (D05-18):** the dashboard uses a **dashboard-local compact row** (`DashboardAssignmentRow.tsx`) — the shared `AssignmentRow` is not modified and not reused; the fields are settled under Decisions → #4.
- **The rows do not own the dialog.** An assignment row's affordance calls the page-level `onOpenDetails(row)` callback (D05-17). If a row were to mount `useAssignmentActions` or open a dialog itself, the page would have two owners of the assignment state and the post-create focus target would be non-deterministic. The section components must therefore receive the callback as a prop from the host (the page, which EP05C owns).
- **The truncation remainder.** `limitRows` reports the remainder; the section shows it as `+N more` under the rows (Decisions → #3).
- **Duplicate content with the full lists.** The dashboard repeats rows the assignments and calendar pages also show; the sections must stay summaries (no editing, no deletion) so the full pages remain the place to work.
- **Time display.** `startTime`/`endTime` are already profile-zone `HH:mm` strings — render them directly. `dueDate` is an ISO **instant**: displaying it in the profile zone needs `formatDate` from `shared/lib/datetime.ts` **with the payload's `timeZone`, not the browser's zone**. This is display-only; the server still owns the arithmetic (and the assumption A7 records the degraded fallback).
- **The page currently renders its own full-screen auth spinner** (`useAuth().isLoading`) — keep that behaviour; the query states are a second, inner layer of loading.
- **The request window must be state, not a `useMemo` over `new Date()`.** A window recomputed on every render would change the calendar query's argument identity and refetch endlessly; a window frozen at mount would go stale across midnight. The page holds the window in state (`useState(() => dashboardTodayRange())`) and the refresh control replaces it (Decisions → #10).
- **The page reads two queries with different argument shapes.** `useAssignmentsQuery()` takes no argument and `useCalendarEventsQuery({ from, to })` takes the window — the hooks must not be called conditionally, and the two `refetch` results are independent.
