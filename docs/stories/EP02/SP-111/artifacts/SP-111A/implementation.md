## Outcome

The `courses` module is the full course-management surface (SP-111A extends the
SP-107B onboarding-minimal module — no duplicate endpoints, D107-9):

- `GET /courses` — the student's courses, `name` asc / `code` asc, active-only
  by default, `?includeArchived=true` adds archived rows (D111-3),
  `?semesterId=` filters to one of the student's own semesters (foreign/missing
  → uniform 404).
- `GET /courses/:id` — any of the student's courses **regardless of archive
  state** (AC-E02-05); missing/foreign id → uniform 404.
- `PATCH /courses/:id` — partial merge of the seven fields; validation on the
  **merged** values; `semesterId` ownership-checked (foreign/missing → uniform
  404, no write); code collision → 409; `isActive` flip archives/restores
  (D111-2) — no hard-delete route exists.
- `POST /courses` — SP-107B behavior unchanged except the new optional
  `instructor` (D111-1) and the extended `CourseWithSemester` response shape
  (D111-4; backward-compatible — the onboarding wizard ignores the extra keys).

Every route is scoped to the JWT principal (`userId` in the `where` clause;
`@CurrentUser()`, global guard); a miss → uniform 404 `Resource not found`
(no existence oracle, repo ownership convention).

## Findings and deviations

- **F111A-1** (fixed, local-only): `prisma migrate dev` refused to run against
  the local dev DB — the previously applied migration
  `20261018232322_semester_course_dates` carries a recorded checksum in the
  local `_prisma_migrations` that differs from the committed file (pre-existing
  local drift; the file is unchanged in Git since SP-107B). Resetting the dev
  DB was not authorized. Worked around: the new migration was hand-written
  (verified byte-equivalent to Prisma's generated SQL), applied directly to the
  local dev DB, and registered in `_prisma_migrations` with the correct
  checksum. Fresh CI/`migrate deploy` databases are unaffected. **Residual:**
  the pre-existing local checksum drift remains in the local dev DB; a
  `prisma migrate reset` would clear it (needs user approval — recorded for
  the user, not a story blocker).
- **F111A-2** (fixed): `semesters-e2e.spec.ts` (SP-110C) pinned the old 8-key
  `POST /courses` shape; D111-4 extends that response to `CourseWithSemester`
  (13 keys). Updated its `COURSE_KEYS` constant + one stale comment. Two tests
  failed until the update; all green after. This is the only cross-module
  change in the child — a direct consequence of the parent-approved contract
  decision, test-only.

Deviations from the ticket: none. The ticket's file list is implemented
exactly, plus the F111A-2 test update.
